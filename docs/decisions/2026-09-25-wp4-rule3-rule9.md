# Rule 3 rewritten as the real number contract, screened against WP3 (WP4)

**Date:** 2026-09-25

## Context

The prompt audit (`docs/reviews/2026-09-24-prompt-audit.md`, finding 3) found that two
SYSTEM_PROMPT rules contradicted each other:
- **rule 3** said "Do not combine or infer numbers that don't appear directly in a search
  result";
- **rule 9** told the model to derive a number "despite rule 3 telling you not to work this
  out yourself -- call `calculate` FIRST".

Rule 3 predates the `calculate` tool, and rule 9 had been patched around it. This is roadmap
Step 4 (WP4). Plan: `docs/plans/2026-09-24-wp4-rule3-rule9.md`.

## Decision

- **4a `7fdfecd`, rule 3.** It now reads: "Every number you state must come from a tool
  result — either stated there directly, or restated in a different unit per rule 9. When
  you need a number derived from others that no tool reports directly (a total, difference,
  ratio, or percentage change), get it from `calculate` rather than working it out yourself
  — its output, like `get_financial_fact`'s, is a single citable value."
- **4a `7fdfecd`, rule 9.** Its clause now reads "If you need to combine, compare, or derive a
  number from values you've already seen, call `calculate` first and cite its result the
  same way as any other;".
- **4b `0675297`:** the `verify_citations` docstring no longer quotes the old rule 3.
- **Review fixes `cd669fe`, `12a2088`, `d204b5b`:** the same docstring was tightened. These
  commits change the docstring only.
- **Fingerprints:** `agent` went from `4f36a2b026cf` to `d2131f5d5aae`. `judge`
  (`2ee29f234c91`) and `mcp` (`3f183b31ab70`) are unchanged.
- **Screen verdict: accepted.**
  - There was no REGRESSED and no REGRESSED-TOTAL flag.
  - The plan's Q4-refusal override signal fired. The replicate run showed noise, so the
    question is recorded as watch and no attribute step ran.

## Why

- **Rule 3 is now stated positively.** It says where numbers come from instead of
  forbidding arithmetic that rule 9 then demands. Rule 9's "per rule 3" stays true.
- **Changes from the roadmap:**
  - **Rule 3 gets the qualifier "that no tool reports directly" (user decision).** Without
    it, the rule sends every ratio or percentage change to `calculate`. That contradicts the
    calculate bullet's "Prefer a named ratio first" and `get_financial_fact`'s `yoy_growth`
    guidance.
  - **The screen also measured two smaller rule 9 edits.** The roadmap's rule 9 text
    lowercases FIRST/ITS and drops the "(a difference, a ratio, a percentage change)"
    examples.
  - **Added:** the docstring commit, 4b. It isn't model-facing, so reverting 4a alone
    restores B's fingerprint.
- **Kept after review, with reasons in the code review:**
  - rule 9's clause doesn't repeat rule 3's qualifier;
  - "derive → `calculate`" is stated three times, in the calculate bullet, rule 3 and rule 9.
    That is audit finding 9, which WP8 files.
