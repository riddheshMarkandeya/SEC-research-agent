# Review: Lucene IDF for per-ticker BM25 indexes

This change makes `_ticker_indexes` build `_LuceneIdfBM25`, adds 2 unit tests, and adds an IDF
check to `tests/manual/verify_bm25_ticker_stats.py`. The suite had 1,399 tests before this diff and
has 1,401 after. The diff is about 70 lines on a critical-core path, so it is reviewed at
**Standard**. The decision is in `docs/decisions/2026-10-09-bm25-idf.md`. There is no repo plan,
because the task is Standard tier.

## Round 1

Passes: `/code-review` medium, `arch-reviewer` (sonnet), `security-reviewer`.

1. **Medium** (code-review): the whole-corpus index (untickered searches) still uses Okapi's
   clamped IDF, so it still has both problems. Words in over half the corpus are lifted above rarer
   words, and a chunk matching only a word in exactly half the chunks is cut at the zero score.
   `[Deferred → BACKLOG]`. This is deliberate scope. The plan review narrowed the change to the
   per-ticker site because the replay holds no untickered query, so a change there would be
   unmeasured.
2. **Low** (code-review): the manual script's check 1 oracle now uses the class under test.
   `[Verified, no fix needed]`. Check 1 is about per-ticker grouping. Check 3 tests the IDF ordering
   against document frequencies counted independently. The plan review already settled this.
3. **Nit** (code-review, arch): the `_bm25_by_ticker` comment tied the misordering to "few chunks".
   It depends on a word being in over half the chunks. `[Fixed]`.
4. **Nit** (arch): `_calc_idf` had no type hints. `[Fixed]`.
5. **Low** (code-review): the override doesn't set `average_idf`. `[Verified, no fix needed]`.
   Nothing in the repo reads it; only rank_bm25's own Okapi `_calc_idf` uses it.
6. **Nit** (code-review): `_rank_bm25`'s cutoff comment said "BM25Okapi returns 0 for no term
   overlap". Under Okapi a score of 0 also covers a match on a zero-IDF word. `[Fixed]`: it now
   says no matched word carries IDF weight.
7. **Low** (code-review): the manual script's `_idf_is_monotonic` both prints and decides, and its
   `min()` isn't guarded against an empty IDF map. `[Verified, no fix needed]`. It is a one-off
   manual script, and the MSFT index always has words.
8. **Security**: no issues. The change adds no inputs, I/O or trust boundary, and the denominator
   `freq + 0.5` can't be zero.

The fixes are comment-only and type-hint-only (nits), so the round is closed.
