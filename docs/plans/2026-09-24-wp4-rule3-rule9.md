# WP4: resolve the rule 3 / rule 9 contradiction (audit finding 3)

## Context
WP4 of `docs/plans/2026-09-24-prompt-audit-roadmap.md` is **Step 4**, audit finding 3
(`docs/reviews/2026-09-24-prompt-audit.md`).
- **The contradiction:** SYSTEM_PROMPT rule 3 says "Do not combine or infer numbers that
  don't appear directly in a search result". Rule 9 says "…derive a number… despite rule 3
  telling you not to work this out yourself -- call `calculate` FIRST".
- **Why it exists:** rule 3 predates the `calculate` tool, and rule 9 was patched around it.
- **The fix:** rewrite rule 3 so it states the real contract (every number comes from a
  tool result; a derived number that no tool reports comes from `calculate`), and drop
  rule 9's "despite rule 3" clause.
- **Screen:** under the Decision rule, against WP3's accepted runs.

**Tier:** Standard. The change is one model-facing commit in `prompts/`, which is
critical-core and on the blast-radius list.

## Changes vs. the roadmap
- **Rule 3 gets a qualifier (user decision).** It reads "a number derived from others
  *that no tool reports directly*".
  - The roadmap's version tells the model to get any ratio or percentage change from
    `calculate`. That contradicts the calculate bullet ("Prefer a named ratio first when
    one exists … use `calculate` only for arithmetic those don't cover") and the
    get_financial_fact bullet's `yoy_growth` guidance.
  - The tension shows already in B: `msft-cash-to-assets-fy2025` uses `calculate
    percent_of` in all 3 runs, although `cash_to_assets` is a registered ratio.
- **Also measured by the screen:** the roadmap's rule 9 replacement also lowercases
  FIRST/ITS and drops the "(a difference, a ratio, a percentage change)" examples. The
  decision file will say the screen measures those changes too.
- **Added:**
  - a docstring fix in `agent.py` (not model-facing);
  - an explicit rule for the Q4-refusal risk (step 6).
